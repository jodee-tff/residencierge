# Lesson 1.4: Commands and Navigation

**Welcome back, [name]. This one is short and mighty.**

You are about to learn four moves that make every future session safer, faster and much easier to control:

1. Reuse a whole set of instructions with `/`.
2. Show the screen instead of wrestling it into words.
3. Ask for a plan before allowing changes.
4. Match the model to the job.

These are not party tricks. They are how you stay in the driver's seat.

## Move one: slash commands and skills

Typing `/` in the message box opens a menu of **commands and skills**: reusable instructions saved with your project.

This might sound confusing, but you've actually been using them all along. Every time you typed `/start-1-2`, you were calling a saved set of instructions, a skill, and it ran the whole lesson for you.

Some entries are built-in commands that perform a fixed action. Others are skills that load a detailed set of instructions for Claude to follow. You do not need to memorise the distinction today. You only need to know that a repeatable process can be packaged as a skill and run again and again, whenever you need it. (And you'll notice more /start commands in that menu than you'll ever type: a few lessons flow into the next on their own, no command needed.)

That idea becomes powerful inside a real business:

- a marketer could run `/monthly-client-report`
- an ecommerce team could run `/review-new-products`
- a gym could run `/weekly-member-risk-check`
- a finance manager could run `/prepare-board-variance-note`

When you wrap your head around skills, they unlock serious value. A repeatable task gets done to the same high standard every time, with less effort. A whole series of tasks can run together, the same way each time, so the results stay comparable: apples with apples.

## Move two: show me the screen

When software is confusing, people often spend five minutes trying to describe a screen that a screenshot could explain in five seconds. A screenshot gives me the same visual evidence you have.

ACTION: Give the shortcut set for THEIR operating system (you can tell which it is); mention the other only if asked.

**On Mac:**

- **Command+Control+Shift+4** = screenshot saved to your clipboard, ready to Command+V into a prompt box, email or document.
- **Command+Shift+4** = screenshot saved to your Desktop instead, where you can drag or upload it.

**On Windows:**

- **Windows+Shift+S** = screenshot saved to your clipboard, ready to Ctrl+V into a prompt box.

Now let's do it for real. Screenshot your prompt box at the bottom of this screen, so I can check you're in the correct folder and have the correct model selected:

1. Press the clipboard shortcut above and draw a box around the prompt area, then let go.
2. Click into the prompt box and press **Command+V** (Mac) or **Ctrl+V** (Windows) to paste it.
3. Hit **Enter**. You don't even need to write a prompt; a screenshot alone tells your AI you want something on that screen identified or fixed.

## Move three: plan before action

This next move might be the most protective sentence you learn all day.

For anything larger than a quick answer, separate **thinking** from **changing**. First, ask Claude to explain what it intends to do. You review the approach, change anything you dislike and approve only when you are comfortable. Then Claude acts.

Have another look in the **inherited-chaos** folder. Deano left four files in there called things like **notes.md**, **more notes.md** and, my personal favourite, **some more notes.md**. Utterly unfindable. Copy and paste this:

```
Make me a plan to organise the messy notes files properly. Don't do anything yet, just the plan.
```

STOP: Paste it and press enter.

USER: Pastes the prompt

ACTION: Read the four messy notes files first (notes.md, more notes.md, some more notes.md, notes from that meeting.md). Present the plan, prefaced with "**Not a single file has been changed yet.**": 1) copy each into organised/ with a descriptive name drawn from what's actually inside (for example "supplier notes - internal.md", "customer notes - 2025 to 2026.md"), 2) add a one-line summary at the top of each copy, 3) group related notes into a subfolder (the two meeting notes into organised/meeting-notes/), 4) leave every original in inherited-chaos/ untouched. Then add: **Why this is the safest plan:** the originals stay put as the record of truth. Once you're happy the new set is complete, deleting the old ones is your call, and yours alone. That is how you make sure I never make a mistake you can't undo. Then: approve it, change it or reject it; a plan from Claude is a proposal, not a royal decree. If you are happy, send:

```
Approved, go ahead.
```

STOP: Approve, amend or reject.

USER: Approves (or amends)

ACTION: Do exactly the approved plan, only inside organised/. Then, in this spirit: **And done.** Open the organised folder. Four unfindable notes became clearly named files, each with a summary at the top, the meetings grouped in their own folder, and every original untouched. From "some more notes" to a filing system, in one approved plan.

## Move four: pick the right engine

What you're learning: Claude comes in different models, and choosing one is like choosing an engine. **Haiku** is small and quick. **Sonnet** is the everyday driver you've been using. **Opus** thinks deeper and takes longer. **Fable** is the top shelf, for the highest-value work only. Bigger is not better. Matched is better.

Feel the difference yourself. Two steps, read both first:

**Step 1.** In the bar below the message box, find the model name and click it. Pick **Haiku**. Then paste:

```
Summarise the customer reviews in one sentence.
```

**Step 2.** When it answers, click the model name again, pick **Opus**, and paste the same line.

STOP: Run both. What did you notice about the speed, and what did you notice about the two answers?

USER: Compares the two [the observation is theirs to make, not yours to hand them. Then one line: for a one-sentence summary, the small engine did the job in a fraction of the time; for the deep work later in this course, the bigger engines earn their keep. Match the engine to the job, and save the top shelf for the moments that deserve it.]

ACTION: Have them click the model picker once more and set it back to **Sonnet**, the everyday driver, before moving on.

*For your business: model choice is a cost and speed dial. Quick jobs on quick models, deep work on deep ones. That one habit keeps AI fast and affordable at scale.*
